Cairn on CarPlay — the Flight Deck

A CarPlay Driving Task app may not draw its own views: the system renders Apple's templates. The only pixels Cairn controls are the UIImages inside list rows — so every gauge here is a Core Graphics glyph handed to CPListImageRowItem and CPListItem.setImage. Row count never changes after connect; only text and images are mutated in place. That is what makes a BLE dropout invisible: nothing reloads, nothing collapses, the needle just goes grey.

The three decks

Holding last-known: the freshness ladder

The dongle notifies at 1 Hz. Cairn never blanks a value — it ages it. One tile, four states, same position, same size, no layout change. LinkHealth.freshness already draws these lines (liveWindow = 3 s, silentAfter = 10 s); the HUD just renders them.

The keystone glyph

The hero row's image is a cairn — four stacked stones, one per DeviceStatus.Health bit (bottom to top: SD, IMU, GNSS, OBD). Filled = OK, hollow = fault, dashed = never reported. It is the only element that can carry colour, so it carries the whole device verdict at a glance.

What is claimed, and on what evidence

"BLE connected" is not "recording". The headline only says Recording when the dongle itself reported tripPhase == .driving and that report is still fresh. Everything else is hedged with its age.
